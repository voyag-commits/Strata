## 1. 概述

本部署包包含 Strata 运行时边缘启动器的完整可重现代码库。它使你能够在任意一台 Windows/WSL 设备上部署并运行 Codex CLI 舰队。

**核心能力：**
- 在 WSL/tmux 中创建命名的 Codex CLI 会话
- 支持一次性启动多个会话（舰队模式）
- 通过 tmux 向运行中的会话注入通知
- 完整保留 BYOR（自带运行时）安全边界：包内不含任何密钥

**部署包内容：**
```
strata-launcher-v0.9/
├── package/          ← v0.9 确定性载荷（TypeScript 源码 + 编译输出 + 规范文档）
├── bin/              ← 三个启动器脚本
├── install.sh        ← 一键安装器
└── 使用手册.md        ← 本手册
```

## 2. 环境要求

## 3. 一键安装

### 3.1 解压并运行

```bash
# 1. 将 strata-launcher-v0.9.zip 解压到任意位置，例如 ~/Downloads/
unzip strata-launcher-v0.9.zip -d ~/Downloads/

# 2. 进入部署包目录
cd ~/Downloads/strata-launcher-v0.9

# 3. 运行一键安装器
chmod +x install.sh
./install.sh
```

一键安装器会自动完成以下操作：

```
阶段 1: 复制 v0.9 载荷到 ~/strata-runtime-edge
阶段 2: 复制启动器脚本到 ~/bin
阶段 3: 安装 npm 依赖并编译 TypeScript
阶段 4: 运行测试并验证安装
```

### 3.2 安装选项

```bash
# 自定义安装路径
./install.sh --target ~/my-strata --bin-target ~/my-bin

# 跳过编译（如果你只想复制文件）
./install.sh --skip-build

# 预览模式（不实际执行，只显示将要做什么）
./install.sh --dry-run
```

### 3.3 安装完成后

```bash
# 将 ~/bin 加入 PATH
echo 'export PATH="$HOME/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc

# 验证安装
strata-fleet-launch --help
```

## 4. 手动安装

如果一键安装器出现问题，可以手动执行以下步骤：

### 4.1 复制载荷

```bash
# 将 package/ 目录复制到目标位置
cp -r package/ ~/strata-runtime-edge

# 进入目录
cd ~/strata-runtime-edge
```

### 4.2 编译

```bash
# 安装依赖
npm ci

# 编译 TypeScript
npm run build

# 运行测试
npm test
```

### 4.3 安装启动器脚本

```bash
mkdir -p ~/bin

# 复制并调整用户名（将 script 中的 hou16 替换为你的用户名）
USER_NAME=$(whoami)

# strata-codex-local（底层启动器 — 包含桥接和密钥路径）
cp bin/strata-codex-local ~/bin/strata-codex-local
sed -i "s|/home/hou16|/home/${USER_NAME}|g" ~/bin/strata-codex-local

# strata-codex-linux-desktop（桌面会话启动器）
cp bin/strata-codex-linux-desktop ~/bin/strata-codex-linux-desktop
sed -i "s|/home/hou16|/home/${USER_NAME}|g" ~/bin/strata-codex-linux-desktop

# strata-fleet-launch（舰队启动器）
cp bin/strata-fleet-launch ~/bin/strata-fleet-launch
sed -i "s|/home/hou16|/home/${USER_NAME}|g" ~/bin/strata-fleet-launch
sed -i "s|PAYLOAD_DIR=.*|PAYLOAD_DIR=\"$HOME/strata-runtime-edge\"|" ~/bin/strata-fleet-launch

# 赋予执行权限
chmod +x ~/bin/strata-codex-local
chmod +x ~/bin/strata-codex-linux-desktop
chmod +x ~/bin/strata-fleet-launch
```

### 4.4 配置提供者

```bash
cd ~/strata-runtime-edge

# 生成默认配置模板
node dist/src/cli.js provider init-template

# 编辑配置
nano .strata-runtime/config/launcher_delegate.local.json
```

确认配置内容为：
```json
{
  "contract_id": "strata.runtime_edge.launcher_delegate_config.v1",
  "provider_name": "local_codex_deepseek_launcher",
  "mode": "exec",
  "launcher_command": "strata-codex-local",
  "launcher_args": [],
  "working_directory": null,
  "healthcheck_args": ["--version"],
  "env_passthrough": ["PATH", "HOME", "USER", "WSL_DISTRO_NAME"],
  "secret_policy": "externalized_no_secret_material_in_package"
}
```

### 4.5 运行健康检查

```bash
node dist/src/cli.js provider doctor
```

如果输出 `"ok": true`，说明安装成功。

## 5. API 密钥配置指南

Strata 采用 **BYOR（自带运行时）** 模式——API 密钥永远不会出现在部署包或 v0.9 载荷中。
密钥存储在你自己维护的 DeepSeek 桥接环境中。

### 5.1 架构概览

```
你的 API 密钥
    │
    ▼
~/.codex-deepseek/ 或 ~/strata/bridge/bridge/.env   ← 只有你知道
    │
    ▼
DeepSeek 桥接进程（本地 HTTP 代理）
    │
    ▼
Codex CLI（通过 --profile deepseek_bridge 连接桥接）
    │
    ▼
Strata 启动器（strata-codex-local 调用 codex）
```

### 5.2 方式一：完整 DeepSeek 桥接配置

这是推荐的生产方式，桥接进程在本地运行，Codex CLI 通过 HTTP 代理连接。

**步骤 1：创建桥接目录**

```bash
mkdir -p ~/strata/bridge/bridge
cd ~/strata/bridge/bridge
```

**步骤 2：初始化桥接项目**

```bash
npm init -y
npm install express dotenv
```

**步骤 3：创建桥接入口文件 `dist/src/index.js`**

```javascript
// DeepSeek API 桥接 — 将 OpenAI 兼容请求转发到 DeepSeek
import express from "express";
import dotenv from "dotenv";
dotenv.config();

const app = express();
app.use(express.json());

const PORT = process.env.PORT || 38441;
const API_KEY = process.env.BRIDGE_AUTH_KEY;
const DEEPSEEK_API_KEY = process.env.DEEPSEEK_API_KEY;
const DEEPSEEK_BASE = "https://api.deepseek.com";

// 健康检查
app.get("/health", (req, res) => {
  res.json({ status: "ok", provider: "deepseek" });
});

// 代理聊天完成请求
app.post("/v1/chat/completions", async (req, res) => {
  try {
    const response = await fetch(`${DEEPSEEK_BASE}/v1/chat/completions`, {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        "Authorization": `Bearer ${DEEPSEEK_API_KEY}`,
      },
      body: JSON.stringify(req.body),
    });

    if (!response.ok) {
      const errText = await response.text();
      return res.status(response.status).json({ error: errText });
    }

    // 流式转发
    if (req.body.stream) {
      res.setHeader("Content-Type", "text/event-stream");
      res.setHeader("Cache-Control", "no-cache");
      res.setHeader("Connection", "keep-alive");
      const reader = response.body.getReader();
      const decoder = new TextDecoder();
      while (true) {
        const { done, value } = await reader.read();
        if (done) break;
        res.write(decoder.decode(value, { stream: true }));
      }
      res.end();
    } else {
      const data = await response.json();
      res.json(data);
    }
  } catch (err) {
    res.status(500).json({ error: err.message });
  }
});

app.listen(PORT, "127.0.0.1", () => {
  console.log(`DeepSeek bridge listening on http://127.0.0.1:${PORT}`);
});
```

**步骤 4：创建 `.env` 文件**

```bash
cd ~/strata/bridge/bridge

cat > .env << 'EOF'
BRIDGE_AUTH_KEY=your-bridge-auth-token-here
DEEPSEEK_API_KEY=sk-your-deepseek-api-key-here
PORT=38441
EOF
```

**步骤 5：获取 DeepSeek API 密钥**

1. 访问 [https://platform.deepseek.com](https://platform.deepseek.com)
2. 注册账号并登录
3. 进入「API Keys」页面
4. 点击「创建 API Key」
5. 复制生成的密钥（格式：`sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`）
6. 将密钥填入 `.env` 文件中的 `DEEPSEEK_API_KEY=` 后面

**步骤 6：编译桥接**

```bash
npm run build
# 如果没有配置构建脚本，确保入口文件存在于 dist/src/index.js
```

**步骤 7：设置桥接认证令牌**

在 `.env` 中设置一个随机的 `BRIDGE_AUTH_KEY`。你可以用以下命令生成：

```bash
# 生成随机令牌
echo "BRIDGE_AUTH_KEY=$(openssl rand -hex 32)" >> .env
```

### 5.3 方式二：Codex 直接使用 DeepSeek（简化）

如果你已经配置好 Codex CLI 的 DeepSeek profile，可以跳过桥接：

```bash
# 配置 Codex profile
codex profile create deepseek

# 编辑 Codex 配置
# 编辑 ~/.codex/config.toml 或通过 Codex 设置
```

然后在 `strata-codex-local` 中确保 `PROFILE_NAME` 设置正确。

### 5.4 方式三：手动 API 密钥注入（非 BYOR，仅限测试）

如果你只是快速测试，可以在 `strata-codex-local` 中直接设置环境变量（**不推荐用于生产**）：

```bash
# 在 strata-codex-local 开头添加：
export DEEPSEEK_API_KEY="sk-your-key-here"
```

**警告：** 此方式将密钥明文存储在脚本中。请仅用于本地测试，不要将此脚本分享给他人。

### 5.5 验证密钥配置

```bash
# 测试桥接健康检查
curl http://127.0.0.1:38441/health

# 应返回：
# {"status":"ok","provider":"deepseek"}

# 测试 Codex CLI 是否正常工作
codex --profile deepseek_bridge "hello, respond with 'strata bridge ok'"
```

## 6. 启动舰队

### 6.1 基础启动

```bash
# 启动 3 个 IC 会话（A/B/C）
strata-fleet-launch --count 3

# 启动指定名称的会话
strata-fleet-launch FLEET-A FLEET-B FLEET-C

# 以 coder 角色启动
strata-fleet-launch --role coder --count 2

# 无头模式（不打开 Windows Terminal 标签）
strata-fleet-launch --count 3 --no-tab
```

### 6.2 预期输出

```
=== Strata Fleet Launch ===
  Payload: /home/you/strata-runtime-edge
  Role:    IC
  Count:   3
  Assigns: FLEET-A FLEET-B FLEET-C
  Tabs:    yes

  STRATA-IC-FLEET-A             tmux=OK  tab=True
  STRATA-IC-FLEET-B             tmux=OK  tab=True
  STRATA-IC-FLEET-C             tmux=OK  tab=True

=== Result: 3 launched, 0 failed ===
```

### 6.3 管理会话

```bash
# 列出所有会话
node ~/strata-runtime-edge/dist/src/cli.js session list

# 捕获某个会话的输出
node ~/strata-runtime-edge/dist/src/cli.js session capture --session STRATA-IC-FLEET-A

# 终止某个会话
node ~/strata-runtime-edge/dist/src/cli.js session terminate --session STRATA-IC-FLEET-A

# 查看 tmux 中的活动会话
tmux list-sessions
```

## 7. 常用命令参考

### 7.1 v0.9 CLI 命令

```bash
cd ~/strata-runtime-edge

# 帮助
node dist/src/cli.js help

# 生成配置模板
node dist/src/cli.js provider init-template

# 提供者健康检查
node dist/src/cli.js provider doctor

# 生成会话名称
node dist/src/cli.js session name --role coder --assignment-id A001

# 启动单个会话
node dist/src/cli.js session launch --role coder --assignment-id A001 --replace

# 列出会话
node dist/src/cli.js session list

# 捕获会话输出
node dist/src/cli.js session capture --session STRATA-CODER-A001

# 终止会话
node dist/src/cli.js session terminate --session STRATA-CODER-A001

# 渲染通知
node dist/src/cli.js dispatch render --notice notice.json

# 注入通知到会话
node dist/src/cli.js dispatch inject --notice notice.json --session STRATA-IC-A001
```

### 7.2 tmux 快捷键

| 操作 | 快捷键 |
|------|--------|
| 从会话中分离 | `Ctrl+B` 然后 `D` |
| 切换到下一个窗口 | `Ctrl+B` 然后 `N` |
| 切换会话 | `Ctrl+B` 然后 `S` |
| 滚动查看输出 | `Ctrl+B` 然后 `[`（使用方向键滚动，`Q` 退出）|
| 水平分割窗格 | `Ctrl+B` 然后 `"` |
| 关闭当前窗格 | `Ctrl+B` 然后 `X` |

### 7.3 向舰队注入消息

```bash
# 向单个会话注入消息
echo "你的消息" | tmux set-buffer -b strata && \
  tmux paste-buffer -b strata -t STRATA-IC-FLEET-A && \
  tmux send-keys -t STRATA-IC-FLEET-A Enter

# 向所有舰队会话批量注入
for S in STRATA-IC-FLEET-A STRATA-IC-FLEET-B STRATA-IC-FLEET-C; do
  echo "hello, fleet member" | tmux set-buffer -b strata && \
  tmux paste-buffer -b strata -t "$S" && \
  tmux send-keys -t "$S" Enter
done

# 通过 v0.9 注入结构化通知
node dist/src/cli.js dispatch inject \
  --notice .strata-runtime/notices/my_notice.json \
  --session STRATA-IC-FLEET-A
```

## 8. 故障排查

### 8.1 `tmux: command not found`

```bash
sudo apt update && sudo apt install -y tmux
```

### 8.2 `node: command not found`

```bash
# 使用 nvm 安装
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
source ~/.bashrc
nvm install 22
```

### 8.3 `codex: command not found`

Codex CLI 需要单独安装。请参考 Codex 官方文档进行安装配置。

### 8.4 `provider doctor` 返回失败

```bash
# 检查配置路径是否正确
cat ~/strata-runtime-edge/.strata-runtime/config/launcher_delegate.local.json

# 确认 launcher_command 指定的脚本存在且可执行
which strata-codex-local
ls -la ~/bin/strata-codex-local

# 确认 strata-codex-local 中的路径正确
cat ~/bin/strata-codex-local | grep -E "NODE_BIN|BRIDGE_DIR"
```

### 8.5 桥接无法启动

```bash
# 检查桥接日志
tail -f ~/.codex-deepseek/wsl-bridge.log
tail -f ~/.codex-deepseek/wsl-bridge.err

# 确认端口未被占用
lsof -i :38441

# 手动测试桥接
curl http://127.0.0.1:38441/health
```

### 8.6 Windows Terminal 标签未打开

```bash
# 检查 wt.exe 路径
ls -la /mnt/c/Users/$USER/AppData/Local/Microsoft/WindowsApps/wt.exe

# 如果 wt.exe 不存在，安装 Windows Terminal
# 从 Microsoft Store 搜索 "Windows Terminal" 安装

# 或使用无头模式
strata-fleet-launch --count 3 --no-tab
```

### 8.7 `npm ci` 失败

```bash
# 删除 node_modules 和 lock 文件后重试
rm -rf node_modules
npm install --ignore-scripts
npm run build
```

## 9. 架构说明

### 9.1 三层启动器架构

```
┌─────────────────────────────────────┐
│     strata-fleet-launch             │  ← 舰队编排层
│     (循环生成ID，调用v0.9 CLI)         │
└──────────────┬──────────────────────┘
               │ 调用
┌──────────────▼──────────────────────┐
│  strata_runtime_edge v0.9           │  ← 确定性载荷层
│  cli.ts → runtime.ts + common.ts    │    永不存储密钥
│    session launch → tmux 会话        │
│    dispatch inject → tmux 注入       │
└──────────────┬──────────────────────┘
               │ 委托
┌──────────────▼──────────────────────┐
│     ~/bin/strata-codex-local        │  ← BYOR 层
│     (Codex CLI + DeepSeek 桥接)      │    密钥在此层
└─────────────────────────────────────┘
```

### 9.2 密钥安全边界

- **v0.9 载荷**：不含任何 `API_KEY`、`DEEPSEEK_KEY`、`sk-*` 令牌
- **启动器脚本**：不含硬编码密钥（需要指向你自己的 `.env` 文件）
- **桥梁 `.env` 文件**：仅存在于你的本地文件系统，从未打包进入部署包
- **验证**：运行 `npm run secret-scan` 确认包内无密钥泄漏

### 9.3 数据流

```
Git 上下文更新
    │
    ▼
调度脚本检测变更 → 渲染通知 → tmux 注入到 STRATA-IC-{assignment_id}
    │
    ▼
IC Codex 会话收到通知 → 执行任务 → 产出报告
    │
    ▼
报告提交到 Git 管理的 Class B → 下次迭代
```
